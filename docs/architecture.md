# システム構成

## 1. 本書の目的

本書では、PWA家計簿アプリケーションのシステム構成、各ファイルの役割及びデータの流れを定める。

具体的な機能仕様は `specification.md`、動作確認項目は `test-plan.md`、設計上の判断と変更理由は `decisions.md` で管理する。

---

## 2. システム全体の構成

本システムは、サーバ側のアプリケーションやクラウドデータベースを使用せず、ブラウザ上で動作するクライアント側のWebアプリケーションとして構成する。

```text
利用者
  │
  ▼
画面（HTML・CSS）
  │
  ▼
JavaScript
  ├─ 画面表示・画面遷移
  ├─ 入力値の検証
  ├─ 家計記録の登録・編集・削除
  ├─ 履歴表示
  └─ 集計処理
       │
       ▼
IndexedDB
  └─ 家計記録の端末内保存

ブラウザからのファイル要求
  │
  ▼
Service Worker
  ├─ ネットワークから取得
  └─ Cache Storageから取得
```

家計記録は外部サーバへ送信せず、IndexedDBへ保存する。

アプリケーションの表示に必要なファイルは、Service Worker及びCache Storageを利用して端末側へ保持する。

---

## 3. 採用する構成

現時点では、次の技術構成を基本とする。

- HTML
- CSS
- JavaScript
- IndexedDB
- Service Worker
- Cache Storage
- Web App Manifest
- Storage API

フロントエンドフレームワーク及びバックエンドは使用しない構成を第一候補とする。

実装開始時に既存リポジトリの構成を確認し、フレームワークを使用する場合は本書を更新する。

---

## 4. 画面構成

本システムは、次の4画面(5画面)で構成する。

```text
ホーム画面
├─ 記録入力画面
├─ 履歴画面
└─ 集計画面

履歴画面
└─ 記録入力画面（編集状態）
```

### 4.1 ホーム画面

主な役割は次のとおりである。

- 今日の支出額の表示
- 今月の支出額の表示
- 記録入力画面への移動
- 履歴画面及び集計画面への移動

### 4.2 記録入力画面

新規登録と編集で同じ画面を使用する。

新規登録時には入力欄を初期状態で表示し、編集時には選択された記録の内容を表示する。

### 4.3 履歴画面

IndexedDBから家計記録を取得し、記録日の新しい順に表示する。

各記録から編集及び削除を実行できるようにする。

### 4.4 集計画面

IndexedDBから取得した家計記録を基に、次の値を算出する。

- 月ごとの収入合計
- 月ごとの支出合計
- 月ごとの収支
- カテゴリ別支出

## 6. 各ファイルの役割

### 6.1 `index.html`

- アプリケーションの基本構造
- 各画面を表示する領域
- 共通ナビゲーション
- JavaScript及びCSSの読み込み
- Web App Manifestの読み込み

### 6.2 `css/style.css`

- スマートフォンを中心とした画面レイアウト
- 入力欄、ボタン及び一覧の表示
- 画面幅に応じた表示調整
- エラー及び完了メッセージの表示

### 6.3 `js/main.js`

- アプリケーションの初期化
- Service Workerの登録
- 初期画面の表示
- 各機能の呼び出し

### 6.4 `js/constants.js`

- 支出カテゴリ
- 収入カテゴリ
- 画面名
- データベース名
- オブジェクトストア名
- その他の共通定数

### 6.5 `js/router.js`

- 表示画面の切替
- 共通ナビゲーションの処理
- 新規登録状態と編集状態の切替
- ブラウザの戻る操作への対応

ルーティング方式は、実装開始時に次のいずれかから決定する。

- URLのハッシュを用いる方式
- JavaScriptのみで表示領域を切り替える方式

### 6.6 `js/db.js`

IndexedDBへのアクセスを担当する。

主な処理は次のとおりである。

- データベースを開く
- オブジェクトストアを作成する
- 家計記録を追加する
- 全記録を取得する
- 識別子で記録を取得する
- 記録を更新する
- 記録を削除する

画面要素の取得や表示処理は行わない。

### 6.7 `js/record-service.js`

家計記録に関する処理を担当する。

- 入力値から家計記録を作成する
- 新規登録処理
- 編集処理
- 削除処理
- 記録日の順に並べ替える

IndexedDBの詳細な操作は `db.js`へ委譲する。

### 6.8 `js/summary-service.js`

家計記録の集計処理を担当する。

- 今日の支出額
- 今月の支出額
- 対象月の収入合計
- 対象月の支出合計
- 対象月の収支
- カテゴリ別支出

集計結果自体はIndexedDBへ保存しない。

### 6.9 `js/validation.js`

入力値の検証を担当する。

- 収支区分の確認
- 金額の確認
- カテゴリの確認
- 記録日の確認
- メモの整形

検証結果は、入力項目ごとのエラーメッセージとして画面側へ返す。

### 6.10 `js/ui/`

各画面の表示処理を担当する。

UI用ファイルから直接IndexedDBを操作せず、`record-service.js`及び`summary-service.js`を介して処理する。

### 6.11 `service-worker.js`

- アプリケーションファイルのキャッシュ
- オフライン時のキャッシュ利用
- 古いキャッシュの削除
- アプリケーション更新時の切替

家計記録の保存処理は担当しない。

### 6.12 `manifest.webmanifest`

- アプリケーション名
- 短縮名
- 起動URL
- 表示方式
- 背景色
- テーマ色
- アイコン

## 7. 家計記録のデータ構造

```js
{
  id: 1,
  type: "expense",
  amount: 1200,
  category: "food",
  date: "2026-06-22",
  memo: "昼食",
  createdAt: 1782080000000
}
```

### 7.1 IndexedDBの構成案

```text
データベース名：
householdAccountingDB

バージョン：
1

オブジェクトストア名：
records

主キー：
id

主キー生成：
autoIncrement
```

必要になった場合は、次のインデックスを検討する。

- `date`
- `type`
- `category`
- `createdAt`

初期実装では全件取得後にJavaScriptで抽出・集計してもよい。記録件数や処理速度に問題がある場合にインデックスを追加する。

---

## 8. データの流れ

### 8.1 新規登録

```text
利用者が入力
  ↓
入力値を検証
  ↓
家計記録を作成
  ↓
IndexedDBへ追加
  ↓
ホーム画面を再表示
  ↓
最新の記録から集計値を再計算
```

### 8.2 編集

```text
履歴から記録を選択
  ↓
識別子で記録を取得
  ↓
入力画面へ既存値を表示
  ↓
変更後の入力値を検証
  ↓
同じ識別子の記録を更新
  ↓
履歴を再表示
```

### 8.3 削除

```text
履歴から削除を選択
  ↓
確認を表示
  ↓
識別子で記録を削除
  ↓
履歴及び集計値を更新
```

### 8.4 集計

```text
IndexedDBから記録を取得
  ↓
対象日または対象月で抽出
  ↓
収支区分・カテゴリで分類
  ↓
金額を合計
  ↓
画面へ表示
```

---

## 9. オフライン時の構成

```text
初回アクセス
  ↓
ネットワークからアプリケーションファイルを取得
  ↓
Service Workerを登録
  ↓
必要なファイルをCache Storageへ保存

通信切断後
  ↓
Service Workerがリクエストを受け取る
  ↓
Cache Storageからファイルを取得
  ↓
画面を表示

家計記録の操作
  ↓
IndexedDBから取得またはIndexedDBへ保存
```

オンライン時とオフライン時で、家計記録の保存先及びデータ形式は変更しない。

---

## 10. 責務の分離

本システムでは、次の責務を分離する。


| 責務            | 担当                     |
| ------------- | ---------------------- |
| 画面構造          | HTML                   |
| 見た目と画面適応      | CSS                    |
| アプリケーション初期化   | `main.js`              |
| 画面切替          | `router.js`            |
| データベース操作      | `db.js`                |
| 家計記録処理        | `record-service.js`    |
| 集計処理          | `summary-service.js`   |
| 入力検証          | `validation.js`        |
| 各画面の表示        | `ui/`                  |
| アプリファイルのキャッシュ | `service-worker.js`    |
| PWAのメタデータ     | `manifest.webmanifest` |


---

## 11. 実装順序

次の順序で実装する。

1. HTML・CSS・JavaScriptの初期構成
2. IndexedDBの接続
3. 家計記録の新規登録
4. 履歴表示
5. ページ再読み込み後の保持確認
6. 編集
7. 削除
8. ホーム画面の集計
9. 月別及びカテゴリ別集計
10. 画面適応
11. Web App Manifest
12. Service Worker及びキャッシュ
13. オフライン動作確認
14. 永続ストレージ要求の検討
15. 公開環境での動作確認

---

## 12. 未確定事項

実装開始前または初期実装中に、次の事項を確定する。

- フレームワークを使用しない構成で進めるか
- 〇既存リポジトリを利用するか
- URLハッシュによるルーティングを採用するか
- 固定カテゴリの最終内容
- 未来の日付を許可するか
- メモの文字数上限
- IndexedDBへ設定するインデックス
- 永続ストレージ要求を実装するか
- 公開先
