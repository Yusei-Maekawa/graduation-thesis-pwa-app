# 実装仕様

## 1. 目的

本書では、PWA家計簿アプリケーションとして実装する機能、画面、データ及びオフライン動作の仕様を定めます。

卒業論文第3章で定めた設計を実装へ落とし込むことを目的とします。

仕様を変更した場合は、実装だけでなく、本書及び卒業論文の該当箇所も更新します。

---

## 2. 実装範囲

### 2.1 必須機能      工程9

* 支出・収入の新規登録
* 登録済み記録の編集
* 登録済み記録の削除
* 履歴の一覧表示
* 今日及び今月の支出表示
* 月別の収入・支出・収支表示
* カテゴリ別支出表示
* 対象月の切替
* IndexedDBへの保存
* オフライン利用
* スマートフォン対応

### 2.2 実装対象外

* 認証
* クラウド同期
* 複数端末対応
* 外部サービス連携
* カテゴリ管理
* 検索・絞り込み
* バックアップ・復元
* 高度な分析
* 通知

## 3. 画面構成

### 3.1 ホーム画面       工程8

役割：

* 現在の支出状況を確認する
* 記録入力を開始する
* 主要画面へ移動する

表示内容：

* 今日の支出額
* 今月の支出額
* 記録追加ボタン
* 共通ナビゲーション

ホーム画面には、詳細な履歴やカテゴリ別集計を表示しません。

### 3.2 記録入力画面  工程6

役割：

* 支出・収入を新規登録する
* 登録済み記録を編集する

入力項目：

* 収支区分
* 金額
* カテゴリ
* 記録日
* メモ

新規登録時と編集時で同じ画面を使用します。

### 3.3 履歴画面

役割：

* 登録済みの記録を確認する
* 編集・削除を開始する

表示内容：

* 収支区分
* 金額
* カテゴリ
* 記録日
* メモ
* 編集操作
* 削除操作

記録日の新しい順に表示します。

同じ記録日の記録については、登録日時の新しい順に表示します。

### 3.4 集計画面     工程9

役割：

* 対象月の家計状況を確認する

表示内容：

* 対象年月
* 収入合計
* 支出合計
* 収支
* カテゴリ別支出

カテゴリ別支出は、支出額の大きい順に表示します。

## 4. 家計記録のデータ構造

一件の支出又は収入を、一件の家計記録として保存します。

```js
{
  id: 1,
  type: "expense",
  amount: 1200,
  category: "food",
  date: "2026-06-22",
  memo: "昼食",
  createdAt: 1782080000000
}
```

| 項目        | 内容          | 必須 |
| --------- | ----------- | -- |
| id        | 記録を一意に識別する値 | 必須 |
| type      | 支出または収入     | 必須 |
| amount    | 金額          | 必須 |
| category  | カテゴリ        | 必須 |
| date      | 支出・収入が発生した日 | 必須 |
| memo      | 補足情報        | 任意 |
| createdAt | 登録日時        | 必須 |

### 4.1 識別子

`id`は、IndexedDBによって自動採番します。

編集及び削除時には、`id`を使用して対象記録を特定します。

### 4.2 収支区分

`type`には、以下のいずれかを保存します。

```text
expense
income
```

### 4.3 金額

`amount`は、0より大きい整数とします。

表示時には桁区切り及び「円」を付加しますが、保存値には含めません。

### 4.4 記録日

`date`は、次の形式で保存します。

```text
YYYY-MM-DD
```

画面表示時には、利用者が確認しやすい形式へ変換します。

### 4.5 登録日時   工程6

`createdAt`は、新規登録時の時刻を数値として保存します。

編集時には変更しません。

## 5. カテゴリ

### 5.1 支出カテゴリ

* 食費
* 日用品
* 交通費
* 趣味・娯楽
* 衣服
* 医療
* 固定費
* その他

### 5.2 収入カテゴリ

* 給与
* 臨時収入
* その他

カテゴリは自由入力とせず、収支区分に応じた選択肢から指定します。

カテゴリ名及び内部値は、実装開始前に最終確定します。

---

## 6. 入力制約

### 6.1 収支区分

支出又は収入の選択を必須とします。

### 6.2 金額

* 必須
* 0より大きい整数
* 小数不可
* 負の値不可

### 6.3 カテゴリ

収支区分に対応するカテゴリの選択を必須とします。

収支区分を変更した場合、変更後の区分で使用できないカテゴリは解除します。

### 6.4 記録日

* 必須
* 有効な年月日
* 新規登録時は当日を初期値とする

未来の日付を許可するかどうかは、実装開始前に決定します。

### 6.5 メモ

* 任意
* 空白文字のみの場合は空欄として扱う

文字数上限は、必要性を確認したうえで決定します。

---

## 7. 登録・編集・削除

### 7.1 新規登録              

1. 入力値を検証する
2. 新しい家計記録を作成する
3. IndexedDBへ追加する
4. 保存完了を表示する
5. ホーム画面へ戻る
6. ホーム画面の集計値を更新する    工程8

### 7.2 編集   工程6

1. 履歴画面で記録を選択する
2. `id`を使用して対象記録を取得する
3. 登録済みの内容を入力画面へ表示する
4. 入力値を検証する
5. 同じ`id`の記録を更新する
6. 履歴画面へ戻る

編集時には、新しい記録として追加しません。

### 7.3 削除　　工程7

1. 削除対象を選択する
2. 確認を表示する
3. `id`が一致する記録を削除する
4. 履歴及び集計結果を更新する

削除後の復元機能は設けません。

## 8. 集計仕様

集計結果はIndexedDBへ保存せず、家計記録から算出します。

### 8.1 今日の支出             工程8

以下を満たす記録の`amount`を合計します。

* `type`が`expense`
* `date`が当日

### 8.2 今月の支出             工程8

以下を満たす記録の`amount`を合計します。

* `type`が`expense`
* `date`が当月

### 8.3 月別収入   工程9

以下を満たす記録の`amount`を合計します。

* `type`が`income`
* `date`が対象月

### 8.4 月別支出  工程9

以下を満たす記録の`amount`を合計します。

* `type`が`expense`
* `date`が対象月

### 8.5 収支     工程9

```text
収入合計 - 支出合計
```

### 8.6 カテゴリ別支出     工程9

対象月の支出記録をカテゴリごとに分類し、金額を合計します。

## 9. データ保存

家計記録はIndexedDBへ保存します。

オンライン時とオフライン時で異なる保存先は使用しません。

最低限、以下の処理を実装します。

* データベースを開く
* 家計記録を追加する
* 全記録を取得する
* 識別子で記録を取得する
* 記録を更新する
* 記録を削除する

データベース名及びオブジェクトストア名は、実装開始時に決定します。

## 10. オフライン利用

### 10.1 前提条件

オンライン状態で一度アプリケーションを読み込み、Service Workerの登録と必要なファイルの保存が完了していることを前提とします。

### 10.2 オフラインで利用可能な機能

* 主要4画面の表示
* 画面間の移動
* 新規登録
* 履歴表示
* 編集
* 削除
* 今日・今月の支出表示
* 月別集計
* カテゴリ別集計

### 10.3 キャッシュ対象    工程12

最低限、以下を対象とします。

* HTML
* CSS
* JavaScript
* Web App Manifest
* アイコン

実際のキャッシュ対象は、実装後のファイル構成に合わせて決定します。

### 10.4 通信回復後の処理

家計記録をクラウドへ送信しないため、通信回復後の同期処理は行いません。

---

## 11. データ保持

IndexedDBに保存した家計記録は、以下の後にも保持されることを目標とします。

* ページ再読み込み
* ブラウザ終了・再起動
* PWA終了・再起動
* オフライン状態での再読み込み

対応ブラウザでは、Storage APIを用いた永続ストレージ要求を検討します。

ただし、次の場合はデータを復旧できない可能性があります。

* 利用者によるサイトデータ削除
* ブラウザまたはPWAの削除
* 端末故障
* 端末紛失
