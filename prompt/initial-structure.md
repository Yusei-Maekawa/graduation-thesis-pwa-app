# 2. 開発するシステム

通信環境がない場合でも、支出・収入の記録、履歴閲覧、編集、削除及び集計を行えるPWA家計簿アプリケーションを開発します。

家計記録は外部サーバへ送信せず、IndexedDBを用いて利用者の端末内へ保存します。

本システムでは、金融機関連携やAI分析などの高度な機能ではなく、必要最低限の家計記録を、通信環境に左右されにくい状態で利用できることを重視します。

# 7. UIに関する方針

UIの最終デザインは、まだ決定していません。

後の工程で、卒業論文に記載した以下の設計方針を基準として複数のUI案を比較し、採用案を決定します。

* 支出・収入の記録を短い操作で開始できる
* 画面上の情報量を増やしすぎない
* スマートフォンで操作しやすい
* 入力内容及び操作結果を理解しやすい
* ホーム、記録入力、履歴及び集計の役割を分ける
* 装飾性よりも操作性と視認性を優先する
* オンラインとオフラインで操作方法を変えない

そのため、工程1では完成されたデザインを作らないでください。

次の範囲にとどめてください。

* セマンティックなHTML構造
* アクセシビリティに配慮したラベル
* スマートフォンで大きく崩れない最低限のCSS
* 後からUIを変更しやすいクラス構造
* 過度な色、装飾、アニメーションを使用しない仮デザイン

UIを独自判断で最終決定しないでください。

1. ブラウザが index.html を読み込む
2. <link> により css/style.css を読み込み、スタイルを適用する
3. <script type="module"> により js/main.js を読み込む
4. DOMContentLoaded イベントが発生し、init() が実行される
5. init() が必要な DOM 要素を取得し、存在を確認する
6. 今日の日付を文字列（YYYY-MM-DD 形式）で算出し、日付入力欄の value に設定する

8. フォームの submit イベントを登録する

主要なHTML要素の役割

<meta name="viewport" ...>：スマートフォンで表示倍率が自動縮小されないようにするために必要。省略するとモバイルブラウザが画面を縮小表示してしまう
<header class="app-header">：アプリケーション名を表示する領域。将来のナビゲーション追加を想定してクラスを付与している
<section aria-labelledby="...">：記録入力と履歴という2つの独立した領域を意味的に分ける。aria-labelledby で各セクションの見出しと関連付けることで、スクリーンリーダーがセクションの目的を把握できる
<fieldset> と <legend>：関連するラジオボタンをひとまとめにし、「収支区分」というグループ名を明示する。fieldset/legend を省略すると、スクリーンリーダーが各ラジオボタンの文脈を読み取れない
<label for="..."> と id="..."：入力欄とラベルを関連付ける。ラベルをクリックしても入力欄にフォーカスが移動するようになる
<p id="form-status" role="status" aria-live="polite">：JavaScriptが仮メッセージを書き込む領域。role="status" と aria-live="polite" を付与することで、スクリーンリーダーがテキスト変化を自動で読み上げる
<script type="module" src="js/main.js">：ES Modules として読み込む宣言。type="module" を指定することで、import/export が使用可能になり、後の工程でファイルを分割して import できる

形式的な確認事項として： <form novalidate> はブラウザのデフォルトバリデーション表示を無効化している。工程3で自前の検証処理を実装するため、現時点でブラウザ側の表示が出ないようにしている。

css/style.css
主要なレイアウト方針

box-sizing: border-box：width: 100% を指定した入力欄がpadding・borderを含めた幅になるようにする。これを省略すると、スマートフォンで入力欄がはみ出す
max-width: 600px; margin: 0 auto;：スマートフォンでは全幅を使い、タブレット以上では中央に寄せる最低限のレスポンシブ対応
width: 100%（入力欄・ボタン）：スマートフォンで指で操作しやすい横幅いっぱいのサイズにする
.form-status { min-height: 1.4em; }：メッセージが表示されていない状態でもレイアウトの高さが確保され、メッセージ表示時のレイアウトシフトを抑える

getTodayString()

何をする：今日の日付を YYYY-MM-DD 形式の文字列で返す
引数：なし
戻り値：string（例："2026-06-24"）
注意点：getMonth() は0始まりのため +1 が必要。padStart(2, "0") で月・日を必ず2桁にする

updateCategoryOptions(selectEl, type)

何をする：<select> の中身を指定した収支区分のカテゴリで作り直す
引数：selectEl（HTMLSelectElement）、type（"expense" または "income"）
戻り値：なし（副作用：DOM を変更する）
注意点：innerHTML = "" で既存の選択肢を全削除してから再構築する。不明な type が渡された場合はコンソールにエラーを出して処理を中断する

init()

何をする：アプリケーションの初期化をまとめて行う
引数：なし
戻り値：なし
処理の順番：DOM要素取得 → 存在確認 → 当日日付の設定 → カテゴリ初期化 → イベント登録

イベントの発生タイミング
イベントいつ発生するかDOMContentLoadedHTML のパース完了時。init() を呼び出す起点change（収支区分）ラジオボタンの選択が変わったとき。カテゴリ選択肢を切り替えるsubmit（フォーム）「記録する」ボタンを押したとき。preventDefault() でページ遷移を止め、仮メッセージを表示する
エラー発生時の処理
DOM要素が取得できなかった場合（id の誤りやHTML構造の変化）は、console.error を出力して return で処理を中断する。存在しない要素への操作を続けると TypeError が発生するため、早期リターンで止める。
